## Intro

The challenge began with a classic <H>performance-vs-cost</H> trade-off. While studying abroad in Ireland, I needed a high-spec server to host a <H>heavy modded Minecraft pack</H> for friends across different timezones. Hosting locally was impossible due to <H>security risks</H> and the need for <H>24/7 uptime</H>. 

My initial, "lazy" cloud setup, leaving a high-spec <H>On-Demand EC2 instance</H> running nearly 24/7, resulted in a single-month bill exceeding <H>$120</H>. This expensive experience highlighted the necessity of cost optimization and became the catalyst for building a <H>smarter, automated</H> system.

## Overview
The goal was to architect a production-grade system providing <H>"on-demand"</H> high-performance gaming with <H>near-zero idle costs</H>. I needed a solution where:

## Technical Implementation

The architecture follows a <H>"Cattle, Not Pets"</H> philosophy. Instead of a single persistent instance, the server lives on an ephemeral <H>Spot Instance</H> that provides up to a <H>90% discount</H> compared to standard rates.

To manage state, I decoupled storage from compute using a standalone <H>Amazon EBS volume</H> tagged `server-files`. On every boot, a master <H>User Data Script</H> programmatically finds the volume, mounts the filesystem, associates a static Elastic IP, and fetches secrets from the <H>SSM Parameter Store</H>.

The user interface is a <H>Serverless Discord Bot</H>. When a user triggers `/start`, a Lambda function verifies the request signature using `PyNaCl` and modifies the Spot Fleet’s target capacity from 0 to 1, initiating a "cold start" of the entire stack.

## Cost Analysis: From "Always-On" to "Pay-as-you-Play"

The primary driver of the original $120 bill was <H>idle time</H>: paying for high-spec compute while friends were asleep or at work. This new architecture shifts the majority of the cost from variable compute to a small set of predictable "flat fees."

### The "Flat Fee"

Even when no one is playing, the system incurs minor costs to maintain the server's identity and data:

<TechStack items={[
  { label: "Elastic IP (EIP)", val: "~$3.60/mo to reserve a consistent entry point." },
  { label: "Amazon EBS", val: "~$0.80/mo to store the persistent world data" },
  { label: "Total Maintenance", val: "~$4.40 / month"}
]} />

### Compute Efficiency
For a standard `t4g.small` (ARM-based) instance, the Spot market price is roughly <H>$0.01 per hour</H>. This is an order of magnitude smaller than the flat fees, meaning a 6-hour session costs only about <H>$0.07</H> in compute.

### Scalability and Modpacks
While this comparison uses a vanilla server as a baseline, the logic remains consistent for <H>high-performance modded servers</H>. Even if a heavy modpack requires a `t4g.large` or `m8g.large` (5-7x the cost), the <H>Spot Instance Pricing</H> and <H>Auto-Shutdown</H> engine ensure that I am still saving <H>70-95%</H> compared to a traditional "Always-On" cloud setup.

At the time of writing, a `t4g.small` spot instance running 24/7 for a month costs $5.20, while a `m8g.large` would cost $19.30 in the <H>us-east-1</H> region. With cost savings from idle-time reductions in mind, the system is clearly a cost efficient upgrade over the lazy system.
