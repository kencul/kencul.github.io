## Overview

Risk of Rain 2 (RoR2) is a fast-paced roguelike with a strict <span className="text-highlight-light">keybinding constraint</span>: the engine natively prevents players from assigning secondary keys to a single action.

This limitation became a major friction point with the discovery of the <span className="text-highlight-light">"Acrid Sprint Bug."</span> By inputting a sprint command over 10 times per second while attacking, players can drastically increase Acrid’s attack speed and health regeneration. Attempting this manually with the default sprint key (Left Control) is not only difficult to sustain but also physically taxing on the wrist.

While the community often uses the mouse scroll wheel to trigger high-frequency inputs, RoR2 only allows binding <span className="text-highlight-light">Scroll Up</span> natively. Binding it also overwrites the primary sprint key, making standard gameplay awkward. Typical workarounds like bloated mouse driver software or external macros require tedious setup and intrusive background processes.

<span className="text-highlight-light">Sprint Double Bind</span> is a BepInEx plugin that bypasses these engine limitations. By hooking into the game’s runtime assembly, it allows players to assign an additional keybind to sprint and enables high-frequency inputs via both Scroll Up and Scroll Down. This restores gameplay flexibility while providing ergonomic access to the Acrid bug.

## Technical Implementation

The project utilizes <H>BepInEx</H> for assembly patching and <H>MonoMod</H> (via `On.RoR2`) to hook into the game’s internal classes. 

A significant challenge was the disparity between Unity's `Update()` (input polling) and the game's `FixedUpdate()` (physics/state processing). To prevent dropped inputs, the mod implements a <H>state-latching pattern</H>: 

<OutcomeList items={[
  { title: "Update()", desc: <>Continuously polls <code>Input.mouseScrollDelta</code> and <code>UnityInput</code></> },
  { title: "Flagging", desc: <>If a valid input is detected, a <code>_keyPressedThisFrame</code> flag is raised</> },
  { title: "FixedUpdate()", desc: <>The hook intercepts <code>PlayerCharacterMasterController</code>, checks the flag, and manually sets <code>sprintInputPressReceived = true</code></> }
]} />

The mod leverages the `Risk of Options API` as a <H>soft dependency</H> to expose configuration handles directly within the in-game settings. By implementing this provider, users can adjust mod options in real-time. This bypasses the friction of manual `.cfg` file editing and game restarts, providing a seamless <H>live-configuration</H> experience.

## Challenges & Solutions

<ChallengeCard items={[
  {
    prob: "Non-Standard Sprint Logic",
    desc: "The game handles sprint states through a unique internal state machine, making it incompatible with standard input-handling methods.",
    sol: "Analyzed existing mod implementations and collaborated with the modding community to identify the precise hooks required to toggle sprinting."
  },
  {
    prob: "Input Desync",
    desc: <>Directly polling input within <code>FixedUpdate</code> led to missed inputs, as high-frequency events (like mouse-scroll ticks) often occurred between physics steps.</>,
    sol: <>Implemented a buffered input pattern: <code>Update()</code> captures and flags the input state, which is then consumed and reset during <code>FixedUpdate()</code>, ensuring frame-perfect reliability.</>
